# Release Guide

This guide explains how to create a new release of `fac`.

## Quick Reference

```bash
# Check current version
make version

# Bump version (choose one)
make bump-patch    # 0.7.5 -> 0.7.6 (bug fixes)
make bump-minor    # 0.7.5 -> 0.8.0 (new features)
make bump-major    # 0.7.5 -> 1.0.0 (breaking changes)

# Build release
make release

# Follow the checklist printed by make release
```

## Detailed Workflow

### 1. Prepare for Release

Make sure your working directory is clean and you're on the branch you want to release from (usually `trunk` or `main`):

```bash
git status
# Should show: working tree clean
```

### 2. Decide Version Bump Type

Follow [Semantic Versioning](https://semver.org/):

- **Patch** (0.7.5 → 0.7.6): Bug fixes, no new features
  ```bash
  make bump-patch
  ```

- **Minor** (0.7.5 → 0.8.0): New features, backwards compatible
  ```bash
  make bump-minor
  ```

- **Major** (0.7.5 → 1.0.0): Breaking changes
  ```bash
  make bump-major
  ```

This updates the `VERSION` file automatically.

### 3. Build the Release

```bash
make release
```

This will:
- Clean previous builds
- Generate the version module
- Compile everything
- Show the version
- Display a checklist of next steps

### 4. Test the Binary

Before committing, test the new build:

```bash
# Test basic functionality
./fac scratch_files/regex_test_examples.txt

# Test version flag
./fac --version

# Test help
./fac --help
```

### 5. Commit and Tag

If everything works:

```bash
# Stage changes
git add VERSION

# Commit
git commit -m "Release v$(cat VERSION)"

# Create tag
git tag v$(cat VERSION)

# Push
git push
git push --tags
```

### 6. Verify on GitHub

Check that:
- The tag appears in releases
- The VERSION file is updated in the commit

## Manual Version Update

If you prefer to set the version manually:

```bash
# Edit VERSION file
echo "0.8.0" > VERSION

# Build
make release
```

## Checking Version on Another Machine

After cloning the repo on a new machine:

```bash
# Clone
git clone <repo-url>
cd facsimile

# Check version (no build needed)
cat VERSION

# Build with that version
make

# Verify it's embedded
./fac --version
```

## Makefile Targets Reference

| Target | Description |
|--------|-------------|
| `make version` | Show current version from VERSION file |
| `make bump-patch` | Increment patch version (x.x.X) |
| `make bump-minor` | Increment minor version (x.X.0) |
| `make bump-major` | Increment major version (X.0.0) |
| `make release` | Clean build and show release checklist |
| `make all` | Normal build |
| `make clean` | Remove build artifacts |
| `make dev` | Build with all warnings |
| `make debug` | Build with debug symbols |

## Troubleshooting

### Version not updating in binary

```bash
# Make sure to clean build
make clean && make
```

### Wrong version after bump

```bash
# Check VERSION file
cat VERSION

# If wrong, edit it manually
echo "0.8.0" > VERSION

# Rebuild
make clean && make
```

### Can't find version module

The `src/version_module.f90` is auto-generated. If it's missing:

```bash
# It will be created automatically on next build
make clean && make
```

## Single Source of Truth

The `VERSION` file is the **only** place you need to update the version number. Everything else is automated:

- ✅ `VERSION` file - **YOU edit this** (or use make bump-*)
- 🤖 `src/version_module.f90` - Auto-generated by Makefile
- 🤖 `./fac --version` output - Uses generated module
- 🤖 `./fac --help` output - Uses generated module

You never need to edit code to change the version!
